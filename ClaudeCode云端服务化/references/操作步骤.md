# Axiom 第一阶段操作步骤

目标：先做出一个最小可运行闭环，证明“HTTP 流式调用 Claude Code + workspace 快照恢复”可行。

## 0. 准备环境

本机需要：

1. Node.js 18+
2. Python 3.10+
3. Docker
4. Anthropic API Key

安装 Claude Code：

```bash
npm install -g @anthropic-ai/claude-code
```

设置 API Key：

```bash
export ANTHROPIC_API_KEY="你的 key"
```

验证 Claude Code 可用：

```bash
claude -p "只回复 ok" --output-format stream-json
```

预期：终端持续输出 JSON 行，最后有完成结果。

## 2. 先做 Mock SSE 服务

目的：先确认 HTTP 流式协议、客户端调用和错误事件没问题，不急着接 Claude Code。

Runtime Service 需要提供：

```http
GET /healthz
POST /v1/query/stream
```

`POST /v1/query/stream` 请求体：

```json
{
  "workspace_id": "ws_demo",
  "prompt": "分析当前项目",
  "cwd": "/workspace",
  "allowed_tools": ["Read", "Grep", "Glob"]
}
```

Mock 阶段 SSE 输出：

```text
event: message_start
data: {"request_id":"req_demo"}

event: content_delta
data: {"type":"text","text":"hello"}

event: final
data: {"status":"completed"}
```

验收命令：

```bash
curl -N \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"workspace_id":"ws_demo","prompt":"只回复 hello"}' \
  http://127.0.0.1:8765/v1/query/stream
```

通过标准：

1. curl 能实时收到多段 `event:` / `data:`。
2. 服务端异常时返回 `event: error`。
3. 正常结束时返回 `event: final`。

## 3. 接入 Claude Code 流式输出

优先级：

1. 首选 Python SDK `claude-code-sdk`。
2. 如果 SDK 事件结构不满足需求，再用 CLI headless 模式兜底。
3. 暂不魔改 SDK。

安装 Python SDK：

```bash
pip install claude-code-sdk
```

SDK 方式要做的事：

1. 把请求体转换成 Claude Code options。
2. 设置 `cwd` 到 workspace 目录。
3. 设置 `allowed_tools`，不要默认开放全部工具。
4. 遍历 SDK 异步消息流。
5. 把 SDK message 转成统一 SSE 事件。

CLI 兜底命令形态：

```bash
claude -p "你的 prompt" --output-format stream-json
```

CLI 兜底要做的事：

1. 使用子进程启动命令。
2. 设置 `cwd` 到 workspace 目录。
3. 逐行读取 stdout。
4. 每一行 JSON 转换为 SSE `content_delta`、`tool_call`、`final` 或 `error`。
5. 子进程超时或非 0 退出码时返回 `event: error`。

验收标准：

1. 真实请求能流式返回 Claude Code 输出。
2. 请求可以读取 workspace 中的文件。
3. 不允许访问 workspace 以外的敏感路径。
4. 不允许默认执行任意 shell 命令。

## 4. 做 Workspace 目录

本地原型约定：

```text
workspaces/
  ws_demo/
    workspace/
    home/
```

运行时环境变量建议：

```bash
AXIOM_WORKSPACE_ROOT=/绝对路径/Axiom/workspaces
AXIOM_SNAPSHOT_ROOT=/绝对路径/Axiom/snapshots
```

每个 `workspace_id` 必须映射到独立目录：

```text
workspaces/{workspace_id}/workspace
workspaces/{workspace_id}/home
```

原则：

1. Claude Code 的 `cwd` 指向 `workspace`。
2. Claude Code 的 home/config 尽量放进 `home`。
3. 不同 workspace 不共享目录。
4. workspace_id 必须校验，只允许字母、数字、下划线、短横线。

## 5. 做全量快照

第一版只做全量 tarball，不做增量。

快照路径：

```text
snapshots/
  ws_demo/
    v1.tar.gz
    v2.tar.gz
```

需要打包：

1. `workspaces/{workspace_id}/workspace`
2. 必要的 Claude Code 项目配置

暂不打包：

1. API key
2. `.env`
3. `node_modules`
4. `.venv`
5. `dist`
6. `build`
7. 日志和缓存

需要实现：

```http
POST /v1/workspaces/{workspace_id}/snapshots
GET /v1/workspaces/{workspace_id}/snapshots
POST /v1/workspaces/{workspace_id}/restore
```

验收流程：

1. 在 `ws_demo/workspace` 写入 `a.txt`。
2. 创建快照 `v1`。
3. 删除 workspace。
4. 从 `v1` 恢复。
5. 校验 `a.txt` 内容一致。

## 6. 做最小 Control Plane

等 Runtime Service 和快照恢复跑通后，再做 Control Plane。

第一版 Control Plane 职责：

1. 接收业务请求。
2. 校验 `workspace_id`。
3. 查找 workspace 是否已有 runtime。
4. 没有 runtime 就启动一个本地进程或 Docker 容器。
5. 把请求转发到 runtime 的 `/v1/query/stream`。
6. 记录 request log。

先不做：

1. 自动扩缩容。
2. Kubernetes。
3. 多机调度。
4. 复杂会话管理。

验收标准：

1. 同一 workspace 连续请求命中同一个 runtime。
2. 不同 workspace 目录隔离。
3. runtime 停掉后能重新启动并恢复快照。

## 7. Docker 化 Runtime Service

镜像里包含：

1. Node.js 18+
2. Claude Code CLI
3. Python 3.10+
4. `claude-code-sdk`
5. Runtime Service 代码

容器启动后：

1. 监听 `0.0.0.0:8765`
2. `/healthz` 返回 ok
3. `/v1/query/stream` 可用

验收命令：

```bash
docker build -t axiom-runtime:dev -f runtime_service/Dockerfile .
docker run --rm -p 8765:8765 \
  -e ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  -v "$PWD/workspaces/ws_demo/workspace:/workspace" \
  axiom-runtime:dev
```

然后调用：

```bash
curl -N \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"workspace_id":"ws_demo","prompt":"列出当前目录文件","cwd":"/workspace","allowed_tools":["Read","Glob","Grep"]}' \
  http://127.0.0.1:8765/v1/query/stream
```

## 8. 第一阶段完成标准

全部满足才进入沙箱池和多用户阶段：

1. 本地 mock SSE 通过。
2. 真实 Claude Code 流式调用通过。
3. workspace 目录隔离通过。
4. 全量快照创建和恢复通过。
5. Docker runtime 通过。
6. 错误事件、超时、日志都有。
7. 默认工具权限是最小白名单。

## 9. 推荐执行顺序

```text
第 1 天：Mock SSE + curl 验证
第 2 天：接 Claude Code SDK 或 CLI stream-json
第 3 天：workspace 目录隔离 + 全量快照
第 4 天：Docker 化 runtime
第 5 天：Control Plane 原型
```

不要一开始就做的事：

1. 不要先做 UI。
2. 不要先接 Kubernetes。
3. 不要先做增量快照。
4. 不要先魔改 SDK。
5. 不要默认开放所有工具权限。
