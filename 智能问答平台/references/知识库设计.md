# 知识库设计

- **日期**: 2026-06-05
- **状态**: 草案
**目标**: 提供知识资产管理与检索能力，承接 OCR 解析结果，沉淀为正式知识，并为 Hermes 提供证据查询能力。

---

## 1. 职责边界

### 1.1 负责

- 接收 OCR 解析结果
- 知识录入
- 知识编辑、分类、标签
- 审核、发布、下线、版本管理
- 可见范围控制
- 构建检索索引
- 提供知识检索与证据结果

### 1.2 不负责

- 文档 OCR 原始解析
- 聊天编排
- 工单、权限、第三方动作执行
- 最终回答生成

---

## 2. 输入输出

### 2.1 输入

- OCR 输出的 Markdown
- OCR 输出的结构化结果
- 管理员编辑内容
- 知识审核动作
- Hermes 发起的检索请求

### 2.2 输出

- 正式知识条目
- 版本与审核状态
- 检索结果
- 证据包 / 引用信息

建议沿用知识管理与 RAG 检索的组合栈：

- `Python 3.12+`
- `FastAPI`
- `PostgreSQL`
- `Elasticsearch`
- `Milvus`
- `Redis`
- `Embedding 服务`
- `Rerank 服务`
- `对象存储`

- `structlog`

## 6. 处理流程

```mermaid
flowchart TD
    O[OCR模型解析结果] --> K[知识录入]
    K --> A[审核/发布/版本]
    A --> I[构建检索索引]
    H[Hermes检索请求] --> R[知识检索]
    I --> R
    R --> E[证据包/引用结果]
```
