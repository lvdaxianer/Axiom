## Context

接口文档要求按设备层级返回电压、电流、负载率、功率、电度、局放和无线测温曲线；还要求全网曲线、地图/列表当前状态、历史时间指针、事件分页和单对象秒级补点。数据源只保存变化点，现场每年约新增 50 亿条，原始数据在线保留一年。客户具备数十 TB 磁盘与数百 GB 内存，但未指定 Apache Doris 版本、对象数、指标数或是否存在对象存储。

这是一项生产架构设计，不是读写压测项目。此前 `time-series-read-benchmark` 变更只适用于 2 TB 单机离线读验证，不能作为生产容量或高可用设计依据。

## Goals / Non-Goals

**Goals:**

- 以设备对象曲线、全网曲线、状态列表和事件查询为驱动，定义可裁剪分区且可预测扫描范围的表结构。
- 原始变化点在线保留 365 天，并采用分区级冷热迁移、归档、校验和删除。
- 将高频访问的当前状态和聚合结果与原始变化点分离，避免缓存成为正确性或性能的唯一依赖。
- 通过受控映射将 PDF 中的 `menuType`、`levelType` 映射到固定表和固定指标，禁止输入参与 SQL 标识符构造。

**Non-Goals:**

- 不实现或修改 Tarsier 业务接口、Doris 建表脚本、Kafka 接入程序或 Redis 客户端。
- 不定义压测计划、并发梯度或性能验收数值。
- 不承诺单机 Doris 高可用，也不承诺超过一年历史数据的实时查询。
- 不以估算行大小替代现场数据压缩率、容量和版本兼容性确认。

## Decisions

### 1. 部署采用多 BE、副本存储和冷热介质分层

生产基线为 3 个 FE 与至少 3 个 BE，关键事实表使用 3 副本。最近 30 天原始数据、当前状态、5 分钟聚合和维表在 SSD；第 31 至第 365 天原始分区在 HDD，或在经版本验证的前提下冷却到对象存储。超过一年后先备份到对象存储并完成校验，再删除日分区。

选择分区级分层而非按行移动，原因是 Doris 的分区裁剪、备份和删除都以分区为自然边界。若版本支持分区存储策略和冷却策略，保持单逻辑表；否则以结构相同的热表和温表替代，服务按时间范围路由并仅在跨边界时合并结果。

不选择单机/单副本生产部署，因为任何单机故障都会同时影响数据可用性与恢复能力；若现场只能提供一台物理机，必须在方案中明确降级风险。

### 2. 原始表保留变化点，聚合表按访问路径拆分

`fact_telemetry_raw` 按 `event_date` 日分区，物理排序前缀为 `(object_id, metric_code, event_time, source_seq)`，按 `object_id` 哈希分桶。它保留变化点和迟到记录，服务只在单对象、短时间范围和秒级窗口中读取它。

`agg_object_5m`、`agg_object_1h`、`agg_object_1d` 的排序前缀为 `(object_id, metric_code, bucket_time)`，保存每个桶的首值、末值、最小值、最大值以及关联时间。全网表独立为 `agg_global_5m`、`agg_global_1h`、`agg_global_1d`，排序前缀为 `(metric_code, bucket_time)`。这避免全网曲线扫描设备明细；单表不能同时为对象和全网查询提供有效的前缀裁剪。

稳定的同报文指标可在原始宽表中保存，利用列式读取只取所需列；可扩展或低频指标使用指标窄表。`cfg_curve_mapping` 是唯一的逻辑指标到物理来源映射，接口不接受任意表名或列名。

### 3. 当前状态、历史状态与历史曲线分离

`fact_current_state` 以 `(object_id, metric_code)` 为唯一键，只服务当前地图和列表。历史时间指针读取对象 5 分钟聚合表的末值；对于需要精确到秒的对象详情，才回读原始变化点。这样不会为所有对象每秒或每 5 分钟强制生成全量快照，避免快照数据量反超变化点数据量。

### 4. 补点在服务层执行，聚合表提供边界与极值信息

服务先读取 `startTime` 前的最近有效值，再读取请求窗口原始点或聚合桶；由服务生成 5 分钟、小时、天或秒的标准时间点并执行前向补点。短周期曲线返回原始变化点和边界补点；长周期曲线返回聚合桶中的极值包络和末值。此决定解决 PDF 中“每窗口最大值和最小值”与示例中多个原始变化点并存的冲突。

### 5. 缓存只服务明确热点，并以数据版本或事件失效

对象树、指标定义和映射配置使用进程本地缓存加 Redis，配置发布时主动失效。地图当前状态和首页固定聚合结果允许短 TTL Redis 缓存，并由状态/聚合更新消息删除相关键。聚合曲线缓存键必须包含对象范围、指标、起止时间、粒度、时区和数据版本。任意原始历史曲线、秒级曲线和大分页结果不得缓存。

不选择缓存所有 API 响应，因为时间轴参数组合过多会导致低命中并挤占内存；Doris Page Cache 是辅助，不是数据正确性或核心查询路径。

### 6. 以数据字节数和副本数计算容量

一年物理容量按 `50 亿 × 实测压缩后字节/记录 × 副本数 + 聚合/索引/当前状态 + Compaction 与临时空间余量` 计算。采购与实施阶段必须以脱敏真实样本确认压缩后字节数、分区数量、冷热介质容量和对象存储恢复能力。不能将“数十 TB 磁盘”直接视为业务数据可用容量。

## Risks / Trade-offs

- **[Risk] Doris 版本不支持所需的分区冷却或对象存储策略** → 使用结构一致的热表和温表，迁移后通过受控时间路由查询。
- **[Risk] 迟到数据落入已迁移或已聚合分区** → 保留明确的迟到窗口；窗口外数据走补录流程，并重算受影响的聚合桶后才发布。
- **[Risk] 单对象定义不清导致站内子设备曲线扫过多对象** → 由 `dim_object` 固化父子关系和 `station_id`，在服务层先解析有限对象集合。
- **[Risk] 原始行压缩率与假设偏差很大** → 以实际压缩后字节数更新容量计算和分区存储配额。
- **[Risk] 缓存失效遗漏导致页面展示旧值** → 当前状态和聚合结果键携带版本，并同时采用事件失效和短 TTL 兜底。
- **[Risk] 秒级接口被用于长窗口导致服务与网络放大** → 只允许单对象且由接口配置限制最大窗口和返回点数。

## Migration Plan

1. 盘点 Doris 版本、物理节点、SSD/HDD 挂载点、对象存储、设备数量、指标基数和源数据迟到上界。
2. 部署对象/指标/映射维表、原始表、当前状态表、对象聚合表、全网聚合表和事件表；在映射未齐全前不切换接口。
3. 将历史数据按日导入原始分区并生成对应聚合分区，逐日校验行数、最早/最晚时间和聚合桶完整性。
4. 接口按对象、全网、状态和事件路径灰度切换；任一新路径异常时回退到既有数据源，不修改或删除原始分区。
5. 启用 30 天冷热冷却、365 天备份与删除调度；每次迁移或删除记录源/目标分区、行数、校验结果、备份位置和执行人。

## Open Questions

- 现场 Doris 版本及是否具备可用的 S3/OSS/HDFS 存储策略。
- 数十 TB 磁盘是否分布在至少 3 台 BE 主机，以及 SSD 与 HDD 的容量比例。
- 原始数据是多指标采集报文还是一行一指标；该信息决定宽表与窄表占比。
- 秒级接口可接受的最大时间窗口与返回点数；本文只要求该上限由服务配置控制。
