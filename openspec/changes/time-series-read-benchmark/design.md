## Context

现有 PDF 需求包含设备层级、指标曲线、事件列表和秒级弹窗。目标服务器只有 2TB 物理磁盘，本次不测试写入吞吐，只在离线装载数据后测试接口读取，且并发梯度固定为 1、3、5。单机 Doris 不能依靠副本提供高可用，磁盘必须为 Compaction、索引、查询临时空间和系统文件保留余量。

## Goals / Non-Goals

**Goals:**

- 用对象维表、指标维表、原始时序表、当前状态表、5 分钟/小时/天汇总表和事件表支撑现有接口。
- 通过分区、排序键、分桶和汇总路由，让单对象曲线与全网曲线分别走适配的访问路径。
- 生成具有变化点、层级、指标、迟到数据和事件特征的可重复数据集。
- 将业务表实际占用控制在 1.4～1.6TB，另行验证接近 2TB 的磁盘压力。
- 以并发 1、3、5 测试当前状态、时间轴、秒级弹窗和事件接口的 P50/P95/P99。

**Non-Goals:**

- 本变更不实现业务接口代码或 Doris 集群高可用。
- 本变更不把 2TB 物理磁盘填满到没有安全余量。
- 本变更不把数据写入耗时计入接口读压测指标。
- 本变更不使用随机填充字段改变正式业务表的压缩和查询特征。

## Decisions

1. **原始层优先保留采集报文宽表。** 如果一条采集记录同时包含多个电气指标，宽表可避免指标拆行造成数据量倍增；服务层用指标汇总表满足曲线查询。只有上游已经是一行一个指标时才使用窄表。

2. **按查询路径拆分汇总表。** 对象曲线使用 `(object_id, metric_code, bucket_time)` 排序；全网曲线使用 `(metric_code, bucket_time, object_id)` 排序。单表无法同时为两类查询提供最佳前缀。

3. **按日期分区。** 原始表和汇总表以 `event_date` 分区，接口查询必须带时间范围。当前状态表不按历史日期分区，事件表按事件日期分区。

4. **状态与历史分离。** `fact_current_state` 使用 Unique Key 保存最新值；`fact_telemetry_raw` 使用 Duplicate Key 保留变化点、重复时间戳和迟到数据。最新状态不能替代历史曲线。

5. **接口参数采用白名单映射。** `menuType` 和 `levelType` 只映射到 `metric_mapping` 中的固定指标和字段，不允许直接拼接用户输入的表名或列名。

6. **容量采用实测闭环。** 先装载小批数据测量 Doris 实际压缩率，再按实际每条占用反推总量。业务表停止在 1.4～1.6TB；若需要测试接近满盘，使用独立 `capacity_fill` 表且不纳入业务接口查询。

7. **读压测使用独立客户端。** 压测客户端不能与 Doris 共用服务器资源。每个场景预热 30 秒、采样 60 秒、重复 3 次，按并发 1、3、5 记录延迟分位数、扫描量和资源指标。

## Risks / Trade-offs

- **[Risk] 2TB 物理磁盘被误当作 2TB 可用数据空间** → 将业务数据限制在 1.4～1.6TB，并在装载前检查系统、索引和临时空间余量。
- **[Risk] 合成数据压缩率与真实数据不同** → 提供真实业务模式和容量填充模式；正式接口压测只使用真实业务模式。
- **[Risk] 全网查询扫描原始表导致延迟失控** → 强制路由到 5 分钟/小时/天汇总表，并在接口层限制最大查询范围和点数。
- **[Risk] 固定参数或结果缓存造成虚高结果** → 随机化对象、指标和时间范围，分别执行冷缓存和热缓存测试，并保留 Doris Query Profile。
- **[Risk] 单机故障不可恢复** → 本计划只做读性能验证；生产部署另行增加外部备份和多节点高可用方案。
