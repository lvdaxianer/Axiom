# 运行、观测与验收

## 1. 部署拓扑

第一期采用单租户、最少组件部署：

```text
Nginx / 内网反向代理
  -> Spring Boot 产品知识助手
      -> SQLite 文件卷
      -> Qdrant Docker 容器与数据卷
      -> OpenAI 兼容模型网关

浏览器插件
  -> Nginx / Spring Boot SSE API
```

需要持久化：SQLite 数据库、Qdrant 数据目录、可信知识目录和导入失败/同步任务日志。模型网关 Key 只通过环境变量或密钥管理系统提供，文档、插件和 Qdrant payload 中不得写入。

## 2. 观测

每个问答请求生成 `requestId`。日志与指标记录结构化技术信息，不保存完整用户问题、证据正文或完整模型回答。

| 类别 | 字段 |
| --- | --- |
| 请求 | requestId、开始/结束时间、总耗时、结果状态、traceId。 |
| 检索 | Qdrant 候选数、SQLite 有效候选数、图谱扩展概念数、跳数分布、Reranker 最终章节数。 |
| 来源 | 最终 documentId / sectionId 列表，不记录正文。 |
| 模型 | embedding、rerank、answer 的模型 ID、耗时、重试次数、成功或错误码。 |
| 索引 | 导入 sourceKey、Hash、section 数、Qdrant job 状态、失败原因、重试次数。 |

统一入口通过 Gateway/Filter 记录 INFO 级请求审计；Controller 只转发，不重复记录。正常外部模型和 Qdrant 调用记录 DEBUG 级耗时；超时、失败和慢调用记录 WARN，并脱敏安全上下文。所有业务日志自动包含 `traceId`；日志框架层统一掩码 `password`、`token`、`apiKey`、`cookie` 等敏感字段，禁止按业务代码手工约定。

Spring Boot 必须在受网络与运维权限保护的 Actuator `/loggers` 上支持包或类级 DEBUG 热开。Qdrant 同步任务、重试任务和模型专用线程池通过 `TaskDecorator` 或等价机制快照并恢复 MDC，任务结束后清理 MDC，防止线程复用导致 traceId 串号。

## 3. 超时和重试

建议初始值，部署压测后调整：

```text
Embedding：连接 3s，读取 15s，最多 2 次重试
Rerank：连接 3s，读取 20s，最多 1 次重试
Answer stream：首 token 20s，总体 90s，不自动重复生成
Qdrant：连接 2s，读取 5s，索引 job 指数退避重试
```

阻塞模型调用必须放在专用有界线程池，不能占用 HTTP 请求核心线程。SSE 客户端断开时取消下游 Answerer 请求并释放上下文。

## 4. 验收集

首期准备 30 至 50 道真实产品问法，至少覆盖：

| 类别 | 示例 | 预期 |
| --- | --- | --- |
| 单文档直接 | “邀请链接过期怎么办？” | 正确章节进入 Top 3。 |
| 中文口语 | “同事的加人地址打不开了。” | 命中邀请链接失效，而非角色权限。 |
| 跨文档 | “重新邀请会不会扣席位？” | 召回操作和计费两份证据。 |
| 覆盖规则 | “旧版限制还有效吗？” | 只使用未被 overrides 覆盖的规则。 |
| 无覆盖 | “怎么申请采购合同？” | 不调用 Answerer，返回 no_knowledge。 |

每条样例至少记录：

```json
{
  "question": "同事的加人地址过几天打不开了怎么办？",
  "expectedSectionIds": ["team_member_management.invitation_link_expired"],
  "expectedConceptIds": ["invitation_link_expired"],
  "mustNotUseSectionIds": ["team_member_management.member_role"]
}
```

## 5. 验收指标

第一期不追求单一模型分数，分层验收：

```text
召回：正确章节是否在 Qdrant Top 20。
重排序：正确章节是否在最终 Top 3。
推理：跨文档问题是否扩展到必要概念和章节。
回答：答案是否仅基于最终来源，是否遗漏关键限制。
拒答：无资料覆盖时是否不调用模型且不编造。
更新：替换一份文档时，其他文档支撑的关系是否保留。
恢复：Qdrant 清空后能否从 SQLite 重建并恢复召回。
```

上线前需对全量样例至少运行一次基线，并保留每次模型、知识目录 Hash 与结果，后续模型或 Prompt 更新必须对比回归。

## 6. 运维操作

### 导入一份文档

```text
1. 在 Codex / Claude 中运行 General Loop。
2. 确认总控 SUCCESS，且文件对进入可信目录。
3. 调用 /api/admin/knowledge-imports。
4. 查看返回 IMPORTED 或 IMPORTED_WITH_INDEX_PENDING。
5. 若 pending，查看 vector_index_jobs，等待或触发重试。
```

### 重建向量索引

```text
1. 停止新的导入任务。
2. 创建新 Qdrant collection。
3. 遍历 SQLite 当前 sections，按配置 embedding model 全量写入。
4. 用验收集验证 Top 20 与 Top 3。
5. 原子切换应用配置到新 collection。
6. 保留旧 collection 至回滚窗口结束后删除。
```

### 故障边界

| 现象 | 首先检查 | 处理 |
| --- | --- | --- |
| 知识未命中 | index job、collection model、section payload | 等待同步或重建索引。 |
| 命中错误章节 | aliases、concept ID、评测样例、Reranker 输出 | 修正知识包或 Prompt 后回归验证。 |
| 图谱过度扩展 | relation type、跳数、远距离候选 | 检查错误关系证据，限制强关系边。 |
| 答案编造 | 最终 evidence 和 Answerer Prompt | 检查是否错误调用模型或缺失拒答分支。 |
| SSE 中断 | 网关超时、客户端断开、专用线程池 | 返回 answer_failed，客户端允许重试。 |
