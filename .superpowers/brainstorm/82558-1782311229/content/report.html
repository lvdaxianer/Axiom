设计文件智能体 · 整体技术方案汇报

模板约束驱动的文档校验与知识治理平台

这套方案面向软件说明类文档的模板入库、指标管理、知识录入、图谱审核、文档校验、结果输出与后续平台化扩展，采用“快速出成果版 + 最终平台版”的双版本路径。

一期闭环模板管理、指标管理、知识库录入、图谱审核、校验、报告输出
二期平台化日志监控、模型管理、编排、问答、广场、权限与审计
校验原则模型负责识别，规则引擎负责判定，人工负责审核发布
存储策略PostgreSQL + 磁盘/NAS + pgvector，后续可平滑扩展

1. 规划总览

系统按底座、知识治理、编排应用、消费入口四层设计。

基础底座

  • 日志与运行监控
  • 模型管理
  • 权限、版本、审计
  • 文件与结构化数据存储

知识治理

  • 指标管理
  • 知识库管理
  • 模板图谱审核
  • 证据链与 chunk 共存

能力编排

  • 智能体流程编排
  • 文档校验节点
  • 知识问答构建
  • 节点调试与发布

应用分发

  • 智能体广场
  • 审核应用
  • 知识问答应用
  • 统一运行入口

2. 两个版本

演示版的目标是快速看到价值，最终版的目标是形成平台能力。

演示版
模板管理

支持软件设计说明、需求规格、标准化工作报告、产品模版、接口设计模版等类型。

演示版
指标管理 + 图谱审核

模型按指标生成候选图谱，人工确认后发布，确保有倾向性且可追溯。

演示版
文档校验闭环

选择模板后校验字号、标题、章节、条件必填项和术语标准引用。

最终版
平台化能力

补齐日志监控、模型管理、编排、问答、广场、权限和告警体系。

3. 推荐技术栈

按“先快后稳”的原则，先选成熟且易二开的组合。

层级 推荐方案 说明
前端 React + TypeScript + React Flow 用于管理台、审核台、广场和节点编排画布。
后端 Python FastAPI 适合文档处理、规则引擎、AI 编排和 API 聚合。
任务调度 Redis + Celery 支持文档解析、录入、校验、重算等异步任务。
主库 PostgreSQL 承载模板、指标、日志、结果、配置和审计数据。
文件存储 磁盘 / 共享 NAS 首期可直接使用本地或共享文件系统，后续再抽象对象存储接口。
向量检索 pgvector 先轻量落地，后续需要再升级专业向量库。
模型层 统一模型网关 接入 LLM、embedding、rerank、OCR、VL、parser 等能力。

4. 核心业务链路

模板入库链路

上传模板 抽取指标 生成候选图谱 人工审核 发布版本

文档校验链路

选择模板 解析文档 装载指标 规则判定 输出问题与依据

知识问答链路

选择知识库 召回 chunk rerank LLM 生成 返回引用来源

编排发布链路

画布编排 节点调试 版本发布 广场分发 运行留痕

5. 一期建议

先把“模板管理 + 指标管理 + 知识库录入 + 图谱审核 + 文档校验 + 报告输出”做成可现场演示的闭环，同时保留人工确认、基础日志和基础模型接入。

6. 风险与边界

建议控制的风险

  • 首期不要同时上全量编排、广场、问答和复杂跨文档校验。
  • 不要把最终判定交给模型，规则引擎必须是主判定器。
  • 不要把图谱做成唯一数据源，指标和证据索引要并存。

建议保留的扩展口

  • 后续可接对象存储，但首期磁盘即可。
  • 后续可替换向量库，但首期 pgvector 足够。
  • 后续可扩多供应商模型和更复杂路由策略。
